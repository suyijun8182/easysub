# debug21 功能遗漏审核

日期：2026-11-01。范围：当前网页版业务代码、安卓设计文档与 `frontend/android-prototype.html`；这是功能迁移审核，不是 APK 完成验收，也不等同于全项目安全审计。

后续补齐进度见 [android-preview-status.md](android-preview-status.md)。本文件保留审核当时的发现，新版已通过独立入口复用网页业务页面；以下缺项不应全部视为仍未处理，也不能据此认定正式 APK 已实现。

结论：当前样稿仅能评估部分视觉与导航，不能作为完整迁移规格。新增页补齐一些字段后，列表、详情、报表、设置、通知与备份仍有大量功能未展示；本地业务与 Android 工程尚未实现。

## 高优先级：数据与业务规则

1. **网页备份实际漏字段。** `backend/app/routers/backup.py:27` 的 `_sub_dict` 与 `:129` 的恢复逻辑不包含 `trial_end`、`cancel_by`、`card_last4`、`card_expiry`。模型与调度器使用这些字段，完整迁移会丢试用/取消/卡到期提醒。AST 字段比对已确认四项缺失。
2. **完整备份范围仍不完整。** 个人导出 `backup.py:271` 不含预算、免打扰/摘要设置、分类显示顺序；个人导入 `:294` 仅恢复通知配置，不恢复导出中的语言、主题、基准币种。整站备份也未完整覆盖预算与提醒偏好。安卓双向迁移须定义统一版本与恢复行为。
3. **离线汇率与记录未纳入备份。** `Currency` 的自定义手动汇率在 `ExchangeRate`，现有备份只导出币种定义，缺汇率缓存/时间、通知日志与操作日志。备份“完整”需明确包括这些本地数据；不能在无网恢复后错误计算。
4. **图标备份不能只存路径。** 当前备份只导出 `icon` 字符串；`/static/...` 与 `/api/icons/library/...` 依赖原服务器。手机需复制真实文件、验证可读取并重写引用；现有 356 条服务目录不是 356 个已离线可用的图标。
5. **续费的两种起算方式缺失。** `subscriptions.py:211`：`today` 从今天开始并重置开始日；`due` 从原到期日推进。样稿只有提示，没有选择及下一到期日预览。必须迁移月末/闰年计算、买断不可续费、最近续费日与通知重排。
6. **付款历史不能从现有数据推断。** `reports.py:167` 只使用每个订阅的 `last_renewed_at` 或买断开始日；数据库没有完整付款流水。样稿的多月趋势是虚构演示，不代表能直接迁移历史账本。保留“最近付款”的实际语义；若要真实历史，需另行确定新增账本范围。
7. **缺汇率不能冒充已换算。** `services/exchange.py:88` 缺汇率时返回原金额。安卓首次离线或自定义币种恢复后必须显示未换算状态，不能把外币原数额标成基准币种。
8. **无 Android 本地实现。** `router/index.js` 强制服务配置与登录；现有 API 层依赖 FastAPI/MySQL，Service Worker 不缓存 API 或图标资源。需要本地数据层、业务计算、启动流程、通知调度、文件/密钥管理与 Android 工程，不能直接包装网页达到目标。

## 中优先级：样稿与规格遗漏

9. **服务选择只完成部分联动。** 样稿 `pickCatalog` 仅填名称和网站，分类控件仍只有少量固定项，图标只是首字母；需迁移网页服务分类映射、内置图标选择与手动覆盖。
10. **新增字段仍不完整。** 网页区分 `remark`（简短备注）与 `notes`（详细笔记）；样稿只有一个备注输入。新增控件多数无数据绑定，付款卡格式、周期、币种等联动仍未实现。
11. **编辑与详情不完整。** 样稿“编辑”打开空白新增页，没有回填；详情没有完整展示现有扩展字段、启停、删除等操作。需验证编辑不会清空折叠字段。
12. **列表操作缺失。** 周期/买断过滤、分类分组与全选、长按/批量操作、手动分类与订阅排序、CSV 导入导出都未体现在样稿中；当前只有搜索、少量分类与到期排序标签。
13. **分类/支付/捆绑包管理没有真实页面。** 需保留自定义分类名称/颜色/图标、编辑/删除及关联处理、支付方式增删、捆绑包加入/创建/移除；下拉控件不等于已实现管理能力。
14. **报表缺少完整内容。** 网页 `Reports.vue:244` 有总览、洞察、分类明细、最近付款四个页签；还包含排行、买断清单、临期/过期清单、周期成本、分类数量/总额与 CSV。样稿仅显示趋势和三类汇总。
15. **日历导航与状态不完整。** 样稿固定 2026 年 11 月，没有前后月、返回今天、整月议程及完整筛选；ICS 导出入口也未实现。需遵守有效状态、日历可见性与无到期日规则。
16. **设置缺少可操作页面。** 语言 zh/en/ru、五主题、基准货币、预算、免打扰、摘要星期、货币/手动汇率、汇率表与更新都需单独覆盖。当前主要是提示与浅深色切换。
17. **14 个外部通知渠道未迁移。** Telegram、飞书、QQ、Bark、Email、Pushplus、Server酱、企业微信、钉钉、Discord、Slack、ntfy、Gotify、Webhook。除开关外，还包括完整参数、测试、Telegram 身份/会话辅助、企业微信自建应用检查与卡片模式、Webhook 多地址/请求头/模板/重试；不能只列渠道名称。
18. **提醒业务细则不够具体。** `scheduler.py` 包含逐日去重、临期与免打扰关系、试用/取消提前 3/1/0 天、卡到期 45 天窗口、每周摘要含未来 30 天/过期事项。手机需明确对应规则、失败重试、各渠道结果及本地通知独立性，不直接照搬服务器去重缺陷。
19. **记录页缺失。** 网页有通知状态/失败信息，以及操作日志的时间、级别、动作、详情；样稿均为提示。需真实记录查询、脱敏、保留及备份策略。
20. **备份流程只有文案。** 文件读取/校验/密码确认、用户选择、数量预览、冲突去重、追加/替换、安全副本、失败回滚、关联重映射、通知重排尚未实现。旧 JSON 与新加密格式的网页兼容代码也未实现。
21. **自动备份细节不足。** 当前服务器每日保存、保留最近 14 份并提供文件列表和立即备份；安卓需确定计划、保留数量、目录授权、密码解锁材料的安全保存、失败状态与手动执行。仅显示“待设置”不足。
22. **移动交互保护仍未实现。** 未保存返回确认、编辑草稿、系统返回栈、批量删除认证替代、通知点击跳详情、进程恢复和权限恢复需落到交互中。五个入口当前不保持完整列表/表单状态。
23. **样稿统计口径有误导空间。** 首页年度/月度是周期折算，不应让“本月预计”暗示当月实际扣款；样稿的分类百分比与年度总额必须与同一演示数据源一致。发布前避免把估算、付款和历史趋势混用。
24. **备份的原始时间与排序关联会变。** `created_at` 未导出，恢复后“最近添加”顺序会变化；整站 `category_order` 保留旧 ID，恢复时却未随分类 ID 重映射。`end_date`、`last_renewed_at`、`created_at` 均需纳入本地模型，即使表单没有编辑入口。
25. **总览不符合已确认的信息优先级。** 当前样稿把金额大卡放在临期事项之前，缺少过期情境、分类总览与最近添加；应先展示需要处理的事项，再展示支出与预算。
26. **无障碍尺寸没有达到设计稿标准。** 样稿辅助文字 10–11px、筛选/日历按钮 36px，与文档辅助文字 14sp、触控目标 48dp 的目标不符；还缺页面切换焦点和选中日期语义。
27. **实体关联删除规则需要明确。** 捆绑包有独立说明 `note`，支付方式有图标；删除捆绑包仅解除关联，不删除订阅。删除被引用分类/支付方式需要阻止或迁移关联，不能只做增删按钮。

规格修正：当前网页没有历史月份趋势与通用时间筛选，原设计中提及的这些内容属于拟新增能力，不能称为网页版既有功能。五个配色主题之外还有跟随系统（auto）模式。外部通知在当前样稿设置中甚至没有完整独立入口，迁移时应补上。

## 已确认的替代边界，不计为遗漏

单人免注册登录；管理员/账号/TOTP/API Token 管理不迁入手机；应用锁保护本地；Home Assistant 继续用网页服务；ICS 采用文件；不做持续自动同步；后台执行受 Android 条件约束。网页端保留这些服务器能力。

## 审核证据与限制

检查来源包括 Vue 路由/各业务页面/通知组件、SQLAlchemy 模型/Pydantic 字段、业务路由、计费、提醒、汇率、图标及备份代码，以及当前设计文档和样稿。对订阅模型与备份序列化做了 AST 字段比对。

本轮只审核并记录，不修改业务代码。未运行真实通知发送、数据库恢复、Android 后台任务、APK 安装/升级或全量安全测试。各项是基于源码确认的缺项或限制，不能据此声称已完成真机功能验收。
