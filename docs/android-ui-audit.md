# EasySub Android UI 审计

日期：2026-11-01。对象：`android-features.html` 及其复用的 Vue 页面、弹层、设计令牌。结论：**未通过手机 UI 定稿审查**。功能入口覆盖比旧稿完整，但目前仍是网页版业务界面加手机样式覆盖，若直接作为 App 界面，会保留一批可达性、信息密度和交互问题。

后续修正与再次检查见 [android-ui-fixes.md](android-ui-fixes.md)。本文件保留初审发现，不代表这些源码问题仍全部存在；实际视觉验收仍待完成。

## 证据范围

已审阅 12 个源码表面：PreviewApp、MobileSettings、mobile.css、全局 theme.css、Dashboard、Subscriptions、Calendar、Reports、Notifications、Logs、NotifyChannels、BaseModal。

尝试检查实际 Chrome 预览，浏览器连接宿主不可用，原生窗口访问返回 `Computer Use was not approved to use Google Chrome`。未绕过该拒绝。本轮没有可用截图、实测 DOM 几何、手机键盘或 TalkBack 验证，以下均标为源码事实、计算或需渲染验证的风险，不声称已经出现全部视觉故障。

本轮仅审计，未修改 UI 代码。checked 12 / changed 0 / left 16：12 个源码表面，0 项 UI 修复，16 项待处理发现。该计数不是截图或视口验收数量。

## 方向判断

保留 Countdown 方向：浅灰底、墨色主操作、绿/琥珀/红表达正常/临期/过期。订阅工具应优先显示待处理事项，使用清晰数字与紧凑列表，不增加营销式标题或装饰动效。

字体沿用现有 Onest 与系统中文回退，先修复尺寸、层级与可读性，不靠更换字体掩盖布局问题。CSS 策略保持现有全局令牌加 Vue scoped 样式，但手机覆盖应围绕组件尺寸契约，而不是用通用 min-height 补丁替代完整适配。

## P1：定稿前必须处理

### 1. 图标网格的轨道和按钮尺寸相互冲突

证据：`Subscriptions.vue:1138` 设置 `repeat(auto-fill, 38px)`、间距 6px；`mobile.css:11` 将 `.lib-ico` 最小宽高设为 48px。

计算：列起点相距 44px，按钮最小宽度 48px，横向至少侵入下一列 4px。160px 的滚动区域还同时承担数百个图标选项。

修复：统一为至少 48px 的网格轨道，加不小于 8px 的间距；图标视觉尺寸与触控容器分离。服务库按分类搜索，图标选择区提供当前选中状态及可见说明。验证 320/360px 宽、长列表与选中焦点。

### 2. 长表单全屏化后没有常驻退出和保存入口

证据：`mobile.css:11` 将所有 `.modal` 统一为 `height:100dvh`；`Subscriptions.vue:202` 的表单仅标题，取消/保存在底部；`BaseModal.vue:49` 默认聚焦第一个输入。

影响：新建时可能立即弹出键盘，挤压服务库选择空间；滚动很长以后才能找到取消/保存。普通返回操作也没有对应的表单页面历史记录。

修复：新增/编辑采用独立页面，顶部提供返回与标题，底部提供明确保存操作；高级字段折叠但全部保留。短续费/删除确认使用内容高度弹层，不与几十字段的表单共用全屏尺寸规则。保留未保存确认。

### 3. 财务指标允许尾部省略，可能隐藏关键数字

证据：`Reports.vue:354` 的 `.stat-v` 使用 `white-space:nowrap; overflow:hidden; text-overflow:ellipsis`，手机稿以两列显示指标。

影响：长金额、货币代码或字体放大后可能显示半个金额。财务数字不能只靠省略号保证容器不溢出。

修复：货币单位与数值分行，长数字采用完整换行或切为单列；如另提供缩写，必须能在同一页面读取完整数值。检查 999,999,999.99、长币种代码与 200% 字体。此处为源码确认的截断规则，尚未取得实际截断截图。

### 4. 统一只扩大按钮高度，触控宽度仍不足

证据：`mobile.css:7` 设置 min-height 48px；`theme.css:120` 图标按钮宽 38px、`:121` 小图标按钮宽 32px；`Subscriptions.vue:1148` 家庭成员移除按钮宽 22px；`NotifyChannels.vue:480` 开关标签高 40px。

影响：形成细长的点击区域，视觉上更高并不等于更好点按。日历七列在 360px 屏幕扣除页边距后，每列最大约 46.9px，还未扣卡片边框和可能的内边距，无法承诺每格都达到设计稿的 48dp 目标。

修复：普通操作目标统一最小 48×48 CSS px 作为 Web 预览目标，不能直接等同实际 Android dp。开关扩大整行点击区域；移除按钮提供不相互重叠的热区。紧凑七列日历使用全格热区，并保留下方宽行议程作为替代操作入口。

### 5. 暗色主题危险按钮对比度不足

证据：`theme.css:51` 暗色 `--late:#ff6b5e`；`:115` `.btn.danger` 使用 `color:#fff`。sRGB 相对亮度计算为 **2.79:1**。

影响：小号白字在亮珊瑚红底上难读。不能通过降低透明度或缩小字号处理。

修复：暗色主题为填充式危险按钮单独定义背景与前景，保留状态文字的原红色语义。以普通按钮文字 4.5:1 为审计目标重新计算，并检查禁用/按下/焦点状态。

### 6. 设置与渠道配置离开时无未保存保护

证据：`PreviewApp.vue:5` 按路由完整路径重建页面；`MobileSettings.vue` 的偏好和 `NotifyChannels.vue` 的配置存放组件局部状态，均没有离开确认。仅订阅表单有 `onBeforeRouteLeave`。

影响：填完通知 Token 或多条 Webhook 后点底栏，内容可以直接丢失，返回仍是旧配置。

修复：明确采用自动保存或显式保存，二者选一；显式保存时显示“未保存”状态、提供离开确认，并为长表单保留会话草稿。验证底栏、系统返回、切换渠道和设置子页四条路径。

## P2：影响日常使用与一致性

### 7. 手机框宽度与响应式断点依据不一致

证据：`mobile.css:1` 内容最大宽 520px；`Calendar.vue:240` 等文件仍依据整个浏览器 viewport 的 860/720px 断点切换。`mobile.css:12` 只补了一部分桌面布局。

影响：桌面上看 520px 宽预览时，日历可能仍使用桌面 112px 高网格、显示小事件名称并隐藏默认议程；真正手机则使用紧凑网格。桌面预览不能代表同宽手机效果。

修复：以预览容器宽度控制手机布局，或将手机预览隔离在真实移动视口中。必须检查浏览器宽度 859/861px 两侧与相同容器宽度，不只查看一张桌面截图。

### 8. 字号系统尚未统一，辅助信息依旧偏小

证据：全局正文 15px；`Reports.vue` 的指标标签 13px、说明/日期 12.5px；`Calendar.vue` 的星期说明 11px；`Subscriptions.vue` 的周期信息及 IP 字体 12–13px。`.android-preview .muted` 只覆盖使用该类的元素，不能覆盖全部语义角色。

修复：形成正文、辅助、数字三个明确角色，对应已确认的 16/14px 起点。不要统一放大每个 `.muted` 来替代组件检查；验证长中文名、英文套餐、俄文和系统大字体。

### 9. 图表分类过多时，环形图不再适合比较

证据：Dashboard 与 Reports 根据分类总数生成环形切片，目录允许十余类，图例需要额外换行或截断。

影响：小屏幕里难比较相邻细小切片。文字列表虽能补充，但图表本身占据较大首屏高度。

修复：2–4 类可保留环形图；更多类别切为按金额降序的水平条形列表，完整显示名称、金额、占比。该项为设计判断，不是已观测的截图缺陷。

### 10. 设置页仍是长目录，且主题显示内部代码

证据：`MobileSettings.vue:6` 一次列出全部 13 个同级入口；`:12` 将 light/dark/ocean/forest/purple/auto 直接显示；自定义设置文案大多硬编码中文。

影响：提醒、数据、外观等任务层级不清楚；切换 English/Русский 后出现混合语言。

修复：按“偏好”“订阅资料”“通知”“数据与隐私”“关于”分组，保持全部入口；主题使用可理解的本地化名称与色板预览，所有新增设置文案接入已有 i18n。

### 11. 顶部预览说明与业务标题重复占据小屏空间

证据：`PreviewApp.vue:3` 固定渲染品牌行，`:4` 每页输出长段预览说明，业务页面又提供自己的 page-head。

影响：用户要先越过预览信息，才能看到临期事项或添加入口。说明在预览中必要，但不应成为最终产品布局的一部分。

修复：预览提示折叠为可展开的短标签；正式产品不带预览口令与工程说明。各业务页只保留一个任务标题层级，不新增营销式大标题。

### 12. 表单和日历的读屏语义不完整

证据：`NotifyChannels.vue:30` 等字段标签与输入为兄弟元素，缺少 for/id 关联或独立可访问名称；日历以 `div role="button"` 实现，只有 Enter 处理，选择状态仅改变 CSS class，议程行没有进入详情的操作。

修复：标签与输入关联；日历用原生按钮或补全键盘及选择状态语义，增加完整日期和事项数量的朗读信息。明确议程行点击查看详情的入口。页面路由切换后管理标题焦点。

### 13. 成功、失败与不可执行状态使用了错误的反馈层级

证据：`mobile.css:10` 的 `.preview-result` 总是绿色边框；`MobileSettings.vue:81` 的 act() 将错误也写入同一个 message。加密能力不可用时仍展示可提交的导出表单；“刷新汇率”与“测试发送”只能返回预览限制。

影响：失败信息看起来像成功，用户需要先尝试才能发现按钮不可执行。

修复：状态包含 success/error/info 类型；错误与对应字段或按钮相邻。明确受限操作的原因，禁用提交或使用“查看正式版流程”入口，避免用可点击按钮假装可执行。

### 14. 部分敏感字段默认明文显示

证据：`NotifyChannels.vue:30` 的 Telegram Bot Token、`:105` 的 Pushplus Token 等未指定 password；其他渠道 Secret 又采用 password，行为不一致。设计稿已要求密钥默认隐藏。

修复：密钥采用默认遮盖、显式显示/隐藏，保留粘贴能力，并使用明确标签说明用途。不要把普通 Chat ID 或服务器地址全部当密钥遮盖。

## P3：视觉完成度与动效

### 15. 动效沿用网页习惯，没有统一手机反馈策略

证据：`Reports.vue:379`、`:399` 动画属性为 width；服务图标和按钮有未限定 hover 的缩放/位移；`MobileSettings.vue` 编辑时直接 smooth scroll，不受 CSS 的减少动画规则控制。

修复：图条使用 transform 或直接更新；触屏不保留悬停位移；高频筛选即时反馈即可。程序触发的滚动根据减少动画偏好决定行为，不仅覆盖 CSS animation。

### 16. 服务图标仍为同色首字占位，不能据此确认最终识别效率

证据：`android-preview/store.js` 服务目录图标生成同色字母 SVG，真实商家图标尚未预置。设计预览可以使用占位，但大量同色图标削弱快速扫读的识别线索。

修复：正式 App 使用离线缓存的真实供应商资源和用户图标；失败时回退首字。替换资源后再检查浅/深色背景、透明边缘、相同首字和长服务名，不能只在占位数据上做最终美观判断。

## 修复顺序与验收矩阵

先修图标网格、全屏表单导航、金额完整显示、触控宽度、危险按钮对比度、未保存保护。随后处理容器断点、字号、设置分组和读屏语义；最后做图表与动效润色。全部功能保留，减少每屏同时展示的层级，不能以删除字段或入口解决拥挤。

需要实际渲染的矩阵：

- 宽度 320、360、390、520 CSS px；短高度 568px；横屏；软键盘展开；字体放大 200%。它们是测试样本，不是声称 OPPO 的实际逻辑分辨率。
- light、dark；ocean/forest/purple 的文字/操作色抽查；auto 随系统切换。
- 总览的空/正常/临期/过期，订阅的长名称/大金额/多选/排序，表单的初始/错误/未保存，渠道的切换/未保存/失败，备份的无能力/解密失败/恢复摘要。
- 默认、按下、焦点、选中、禁用；底栏、安全区域、系统返回与 TalkBack。

推荐直接检查：`http://localhost:5174/android-features.html#/subscriptions` 打开“添加订阅”及图标库；`#/reports` 放入大金额；`#/settings/channels` 切换配置；`#/settings/preferences` 切换暗色后检查删除按钮。只有取得渲染/截图和真机操作证据后，才能关闭对应条目。
