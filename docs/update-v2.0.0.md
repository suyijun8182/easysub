# 升级到 v2.0.0

本版保留外部 MySQL、数据卷和已有账号，增加账号安全、整站加密灾备和通知出站限制。
整站备份接口和出站默认策略存在相容性变更，因此版本升为 2.0.0。

## 升级前

1. 在旧版导出个人及整站备份，并保存 MySQL 快照、Compose 配置、原 `JWT_SECRET` 和数据卷副本。
2. 为自动整站备份配置独立的 `BACKUP_PASSWORD`，至少 12 位，另行保存；留空时自动备份会暂停并显示提示。
3. 如果通知、SMTP、图标下载或代理使用内网地址，配置 `OUTBOUND_PRIVATE_ALLOWLIST`，填写逗号分隔的精确 `host:port`，例如 `nas.lan:5000,192.168.1.10:7890,api.telegram.org:443`。

使用代理时，代理地址与目标地址都需要显式列出，即使目标当前解析到公网。
白名单域名及代理属于管理员信任的目标，应只允许实际使用的服务；不支持通配符或整个网段放行。
未启用 TLS 的 SMTP 不会退回明文登录，请使用 SSL 或支持 STARTTLS 的邮件服务器。

## Docker

将现有 app 服务镜像固定为 `suyijun8182/easysub:v2.0.0`，或 `ghcr.io/suyijun8182/easysub:v2.0.0`。
在现有 Compose 项目内运行：

```bash
docker compose pull app
docker compose up -d app
docker compose logs --tail=100 app
```

保留已有 MySQL、数据卷和 `JWT_SECRET`，不要执行 `down -v`。
启动时自动补齐认证版本、两步验证待确认密钥和验证码限制字段，既有账号和业务资料保持不变。
本地没有配置生产数据库时，健康端点只能证明进程可访问；已有部署还需确认数据库状态正常。

## 备份和账号

手动整站导出需要在设置中输入至少 12 位的独立备份密码，恢复时填写同一密码。
导出接口改为 `POST /api/backup/export-all`，JSON 请求体为 `{"password":"独立备份密码"}`，不要将密码放入 URL。
新文件为 `encrypted-full-v1`，使用 PBKDF2-SHA256 和 AES-256-GCM，与服务器的 `JWT_SECRET` 无关。

旧明文备份仍可导入；旧文件未包含两步验证字段时，恢复不会关闭已有账号的两步验证，但无法替新建账号找回原本未备份的密钥。
新整站备份包含已启用的两步验证状态和密钥，不包含待确认密钥或登录会话。
个人业务导入不恢复账号认证材料；Android 可解密新整站文件并选择一个账号的业务资料。
账号密码、两步验证确认变更或整站恢复后，旧 JWT 会话失效；API Token 和日历链接是独立凭据，本版不自动撤销它们。
App 本地资料和待同步修改继续保留；服务器恢复导致同步世代改变时，App 会暂停同步，需先备份本地资料再按提示重新关联。

## Android Alpha

安装附件 `EasySub-0.1.3-alpha-debug.apk`，覆盖同签名 Alpha，避免卸载造成资料丢失。
Android 版本码为 3，Web/服务端版本为 2.0.0，前端私有 npm 包版本不作为产品版本。
本次修复跨日续费、自定义币种导入同步和新整站备份解密，未包含原工作区的 debug23 至 debug25 界面改动。
系统通知、后台任务、设备认证、正式发布签名及完整真机验收仍未完成。

## 验证与回滚

升级后检查：账号登录及两步验证、旧会话失效、备份导出和隔离恢复、各通知渠道测试、App 离线修改及双向同步。
重试任务每 5 分钟检查仍适用的失败提醒，逐渠道退避，当天每个渠道最多尝试 5 次；成功渠道不重送。
通知调度按单 app 实例、单 worker 使用，暂不提供多实例恰好一次投递保证。

需要回滚时，将 app 镜像固定为 `v1.14.1`，保留数据卷，重新创建 app 容器；新增数据库列可保留。
旧版无法读取新的加密整站文件，若需恢复旧版数据，使用升级前保存的旧格式备份或 MySQL 快照。
安全修复在旧版不会生效，回滚只适合作为故障恢复措施。

实现依据：[HTTPX 自定义传输](https://www.python-httpx.org/advanced/transports/)、[HTTPCore 网络后端](https://www.encode.io/httpcore/network-backends/)。
