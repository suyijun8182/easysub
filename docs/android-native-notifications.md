# Android 本地到期通知设计

日期：2026-11-16。状态：规则与依赖选择已由用户确认，进入实现；尚未真机验收。

## 范围与已核实事实

本功能从 Android 本地订阅数据计算提醒，交给系统排程，不依赖服务器推送。网页入口不加载插件，不修改后端提醒逻辑。只处理有效订阅；不模拟用户尚未记录的未来续费周期。

已阅读 `backend/app/services/scheduler.py`、`notify.py`、Android 预览 store、启动入口和本地同步保存流程。服务端的实际规则为：

- 续费：仅周期订阅，按 `next_renewal_date` 与 `remind_days_before` 中的非负整数天数匹配；空白及无效片段忽略，重复天数只产生一条。
- 试用和取消截止：分别针对 `trial_end`、`cancel_by` 的提前 3、1、0 天；有效的一次性订阅也可有这两类提醒。
- 付款卡：`card_expiry` 为 MM/YY 或 MM/YYYY，换算为该月最后一天，剩余 0 至 45 天时符合条件。

用户确认 Android 付款卡提醒只在到期日前 45、30、7、1、0 天发送，到期日按有效期当月最后一天计算，与 `_card_expiring` 一致。网页端在 45 天窗口内每天提醒；此差异是明确的产品选择，网页端和后端不改。

## 依赖与原生能力

npm 元数据核实的最新稳定版为 `@capacitor/local-notifications` 8.3.1，peer dependency 为 `@capacitor/core >=8.0.0`。已将发布 tarball 解到忽略目录检查，尚未修改依赖清单。该版本 SDK 默认值为 compileSdk 36、minSdk 24，使用 JDK 21，与当前工程一致。

用户允许官方依赖内部使用 Kotlin：8.3.1 模块加载 `kotlin-gradle-plugin` 2.0.21 并应用 `kotlin-android`。EasySub 新增原生代码仍只写 Java，不向 App 模块增加 Kotlin 插件。必须通过 `build-apk.ps1` 构建，报告中列出 Kotlin / AGP 警告。

使用 8.3.1，接入须处理以下已核实的行为：

- 插件 manifest 声明 `POST_NOTIFICATIONS`、`RECEIVE_BOOT_COMPLETED`、`WAKE_LOCK`，也声明 `SCHEDULE_EXACT_ALARM`。App manifest 用 `tools:node="remove"` 删除精确闹钟权限，且不加入 `USE_EXACT_ALARM`。构建后检查最终合并 manifest。
- 每条通知显式传 `isExactNotification: false`，使用普通调度，不调用精确闹钟设置入口。可能有数分钟偏差；省电、Doze 或厂商后台限制可能造成更长延迟，不承诺准点。
- `schedule()` 内部可能申请通知权限。应用先检查权限与总通知开关，未获授权时不调用 `schedule()`，避免启动和自动重排触发权限弹窗。
- 通知构造器使用 `VISIBILITY_PRIVATE`；创建独立的到期提醒渠道时仍需显式传 `visibility: 0`，因为插件渠道默认值是公开。系统锁屏策略仍由用户控制，真机需核验默认隐藏内容的表现。

参考：[Capacitor v8 官方通知 API](https://capacitorjs.com/docs/apis/local-notifications)。具体行为以已检查的 8.3.1 发布源码为准，升级依赖时重新核对。

## 纯 JS 排程

模块为 `frontend/src/android-preview/reminder-schedule.js`，不导入 Capacitor，使用 `node --test` 验证。输入为订阅列表、通知设置、当前时间、IANA 时区及 App 当前语言；输出每条包含 `id`、`at`、`title`、`body`、`extra: { subscriptionId, kind }`。

日历运算使用指定时区的日期和本地时刻，不以固定 24 小时相加代替跨日运算。默认本地时间 09:00，只保留当前时间之后且不超过未来 60 个日历日窗口的通知。排程时刻须转换为真实时间点，覆盖跨月、闰年与夏令时切换；过去的 09:00 不在每次打开 App 时补发。

免打扰开始等于结束时视为未开启；支持同日区间和跨午夜区间。普通提醒落在免打扰内时顺延至该段的 `quiet_end`，顺延后再次检查窗口。续费在投递当地日期的今天或明天到期时允许突破免打扰；试用、取消截止和付款卡不使用紧急突破。后端日期提醒尚无此顺延逻辑，本地按本计划统一执行。

ID 使用订阅 ID、类型、提醒日期计算稳定哈希，限制在正 32 位整数。输入顺序变化不能改变 ID；同一日期重复规则去重，并测试 ID 冲突处理，避免系统覆盖另一条提醒。按时间及稳定键排序，仅取最近 64 条。上限控制本机排程及重启恢复成本，超过时保留最近事件；不是声称 Android 仅支持 64 条。未来事件依靠后续重排进入列表，长期不打开 App 时无法保证 60 天之后继续提醒。

通知文字使用 App 当前语言，中、英、俄均包含订阅名、金额与币种、对应事项和日期。切换语言或修改订阅后重新计算；不把服务器渠道是否启用当作系统本地通知的开关，也不把每周摘要误作四类到期事件之一。本项不新增每周摘要通知实现。

## 接入、权限与失败表现

启动完成、订阅或提醒设置保存、本地恢复、同步写入和回到前台后，经过约 2 秒防抖重新排程。接入启动入口及本地数据变化回调，避免修改共用同步引擎；浏览器预览 `isAndroid()` 为假时不导入或调用原生插件。

每次重排先计算完整新列表，再串行取消之前由到期提醒模块登记的通知、写入新列表。保留自身 ID 或类型标记，不能使用全局取消把未来独立的同步通知也删掉。并发修改时重新计算最新状态，避免旧异步任务把删除前的提醒写回。权限被拒绝时仍计算列表，但不调用通知排程；可在插件允许的范围清理残留通知。

“提醒设置”显示“已允许 / 未允许 / 系统不需要”三语状态。Android 13 及以上仅由用户点申请按钮触发授权；拒绝后显示系统设置入口。旧系统不需要运行时权限，但仍检查系统通知总开关，不能把系统禁用误报为已允许。返回设置页或 App 前台时刷新状态。

Android 系统设置入口用现有 Java 设备插件增加通知设置方法，优先打开 App 通知设置；失败回退应用详情设置。单元测试与真机分别验证权限分支和设置入口，不把浏览器预览状态当作真机授权结果。

权限拒绝不弹错误。排程异常不能导致订阅保存或同步失败，设置页以三语状态说明尚未完成排程，允许下次前台或数据更新重试，不显示虚假成功。点击通知时等待本地数据及路由可用，订阅存在就进入详情，不存在则进入总览；启动点击与前台点击均需测试。

## 重启恢复与调试验收

8.3.1 的 `NotificationStorage` 持久化排程；manifest 注册 `LocalNotificationRestoreReceiver` 处理 `BOOT_COMPLETED` 等广播。接收器检查用户已解锁后读取排程，重新交给通知管理器；已触发的一次性通知不重复登记。因此先用插件自带恢复，不预先增加第二份接收器。源码存在不能代替本机重启验收。

真机先登记隔离测试提醒，重启后不打开 App，检查 `dumpsys alarm` 与系统通知。如果本机无法恢复，再定位原因，必要时用 Java 增加恢复接收器及测试，避免重复恢复。

测试通知只针对 `DEVICE_TEST_NOTIFY`。为缩短等待使用仅 debug 构建可用的测试入口，校验订阅名称前缀、限制触发时间且经过正式排程通路；release 中没有入口。不得修改系统时间，不得操作其他订阅。测试结束删除隔离订阅、检查残留排程并恢复更改过的通知权限及开发者设置。
