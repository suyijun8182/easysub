# v1.14.0 更新与回滚

本版为网页服务器增加 Android App 同步协议。仅更新 APK 不会让旧服务器支持同步；服务器也需更新到 v1.14.0。

镜像：`suyijun8182/easysub:v1.14.0`，备用：`ghcr.io/suyijun8182/easysub:v1.14.0`。均发布 amd64 和 arm64。建议固定版本标签，验证完成后再自行选择是否使用 latest。

## 1. 升级前保留数据与原配置

- 在网页“设置 → 数据备份”导出个人数据；管理员可导出整站备份。备份包含通知密钥，应离线妥善保管。
- 对现有 MySQL 做一次数据库备份。JSON 导出不能代替完整数据库备份。
- 保存原来的 Compose 文件、`.env`、端口和反向代理配置，以及 `/app/data` 数据卷或宿主目录。`/app/data` 包含数据库连接配置、图标及可能存在的服务器自动备份。
- **保留原 `JWT_SECRET`**，不要重新生成。通知密钥及同步密文由它派生加密；更换会导致旧密文无法解密。原 MySQL 地址、账号和数据库名也应保持。
- 记录现用镜像完整版本或 digest。上一版本为 v1.13.0 时，可用该固定标签回滚；若当前使用其他版本，记录实际版本。

## 2. 更新现有容器

### NAS 图形界面

在现有项目/容器上编辑镜像为 `suyijun8182/easysub:v1.14.0`，拉取并重新创建。保留原数据卷、环境变量、网络、端口和反向代理。不要新建空的数据卷或重新执行安装向导。

### Docker Compose

进入**原来的 Compose 项目目录**，将 app 服务 image 改为上述固定标签，然后执行：

```bash
docker compose -f docker-compose.hub.yml pull app
docker compose -f docker-compose.hub.yml up -d --no-deps app
docker compose -f docker-compose.hub.yml logs --tail=100 app
```

使用你实际的 `-f` 文件和 `-p` 项目名；若服务不是 app，替换为原服务名。原来没有 `-f` 就继续使用原命令。不要换目录或项目名而意外连接到新的空卷，也不要执行 `down -v`。原来通过 `docker run` 部署的，用原环境、网络、端口和挂载配置重新创建，仅替换镜像标签。

本版启动时创建 `sync_states`、`sync_records`、`sync_changes`、`sync_receipts` 四张表，并将既有同步密文字段幂等扩为 LONGTEXT。数据库账号需要相应 CREATE/ALTER 权限。原订阅表不重建；MySQL 连接使用 READ COMMITTED，网页写入与同步日志在同一事务中提交。

## 3. 确认服务器升级成功

打开 `https://你的域名:端口/api/health`，应返回包含：

```json
{"status":"ok","configured":true,"version":"1.14.0","sync_protocol":1}
```

再打开 `/openapi.json`，确认存在 `/api/sync/v1/capabilities`、`/changes`、`/push`。未登录访问 capabilities 返回 401 JSON 是正常鉴权；返回 HTML 表示仍是旧容器或反向代理指向了旧服务。

若 configured=false 或出现数据库权限错误，先查看 app 日志与原数据库连接、数据卷，不要把生产数据库当作全新安装重配。反向代理需转发 `/api/` 并允许 Authorization 请求头；不要改变原对外域名和 HTTPS 端口。

## 4. 手机连接和联调

安装 Release 附带的 Android Alpha APK（不是正式签名生产版）；已有 Alpha 使用覆盖安装，保留本地数据。手机“账号与同步”填写原网页服务器地址和已有账号，测试连接，核对账号与记录数量后保存。

首次连接不因另一端缺记录而删除资料。同名但不同身份的记录保留，可能需整理重复项。本地改过的偏好与通知配置若和服务器不同，会保留双方版本供选择，未改过的采用服务器配置。已有配置不会静默覆盖丢失。

先用一条明确命名的测试订阅验证：手机新增出现在网页、网页修改回到手机、同一记录双改出现冲突；确认后再清理该测试记录。服务器尚未升级、地址或账号不符时，不应上传本地资料。

Android Alpha 已验证本地新增/删除、冷启动数据保留与 Keystore 加密存储；系统通知、后台任务、设备认证及完整离线/备份恢复验收仍待完成。网页原有通知渠道保持服务器处理，避免把 Alpha 当作已完成的原生功能。

## 5. 回滚

若本次更新出现问题，先暂停手机自动同步，将**原项目**的镜像改回记录的旧版本/digest，再用原命令重建 app 服务。保持数据库、数据卷和 JWT_SECRET 不变。新增同步表可以保留，不手工删除它们；旧版本不会提供 App 同步接口，手机会暂停同步并保留待传数据。

只有确实需要回退业务数据时，才在停写状态下恢复升级前的完整 MySQL 和匹配的数据卷备份；这会回退备份之后的修改，需要先另存这些新增资料。
