# debug22：网页与 Android 自动双向同步规格

状态：用户已确认方案并授权实施。已实现服务器协议和独立持久化浏览器测试客户端，尚未完成 Android 原生交付。来源：`需要实现的功能.txt:191`。本需求取代 debug21 中“不做自动同步”的范围约定，不取代离线可用、本地保存与完整备份要求。当前实现与验证边界见 `debug22-sync-status.md`。

## 目标

用户在 App「设置 → 服务器与同步」填写自己的 EasySub 地址、账号、密码，测试连接并保存。关联后，网页和手机对同一账号个人数据的新增、编辑、续费、分类调整及删除可自动同步。离线修改先在本地成功保存，联网后补传，不因服务器不可用阻塞本地使用。

新增用户要求：填写的账号未在所连接的 EasySub 网页服务注册时，提示注册并提供入口。注册属于该服务器账号，不另建一套手机账号；已有网页账号可以直接登录。

原设计预览仍使用会话内存。新增独立浏览器客户端提供加密 IndexedDB 和真实同步，不会上传演示资料。正式 Android 交付仍须接入原生安全存储、生命周期和真机验证。

## 现有代码事实

- `/api/auth/login` 使用表单账号密码，开启 TOTP 时还需验证码；`/api/auth/refresh` 返回新访问/刷新令牌。
- 现有业务使用 FastAPI、SQLAlchemy、MySQL，网页 Vue 页面通过统一 axios 层访问。
- 当前模型没有用于同步的稳定跨设备标识、记录版本、删除墓碑或持久化客户端操作队列。
- 当前 JSON 备份漏掉部分订阅字段、用户偏好与关联数据，不可直接作为可靠同步协议；完整备份与同步序列化需先统一字段清单。
- App 预览的 API adapter 只操作会话内存，不可悄悄改成连接真实服务器，否则演示操作会写入用户数据。

## 拟采用的默认规则

1. 同步为可选功能；不连接服务器也能单机使用。每个本地资料库只关联一个服务器账号。
2. 地址、账号、密码及可选两步验证码用于连接测试；成功后保存服务器身份、账号身份与令牌，密码和一次性验证码不长期保存。
3. 不同记录独立合并。同一记录在两端均改变时保留双方版本，提示用户选择，不按手机时间或最后上传时间静默覆盖。用户已确认默认方案。
4. 首次连接只合并，不按某一端“缺少记录”推断另一端应删除。明确展示两端数量与可能重复项；无匹配身份的记录默认保留。
5. 明确删除才同步删除事件；修改与删除冲突也需用户处理，不复活已删除记录，也不静默丢弃离线编辑。
6. 更换服务器/账号前暂停同步，保留旧资料的本地副本；新账号使用独立资料库或经用户明确确认后迁移，禁止跨账号自动混合。
7. 断开关联只停止同步并清理关联凭据，保留本地数据；不顺带删除服务器数据。

## 同步范围

| 类型 | 处理 |
| --- | --- |
| 订阅/保号 | 全部业务字段，包括付款/续费时间、试用、取消截止、卡末四位与有效期、家庭成员、VPS、备注与详细笔记 |
| 分类/支付方式/捆绑包 | 自定义实体及关联、分类颜色/图标/排序、捆绑包说明；系统预设需提供稳定引用与明确修改权限 |
| 自定义币种与手动汇率 | 同步自定义定义及手动值，标记汇率基准；公共联网汇率作为有时间戳的服务器缓存下发，不让离线陈旧值覆盖更新缓存 |
| 图标 | 上传资源或内嵌图的文件内容及内容标识；不能仅同步旧设备或服务器上的字符串路径 |
| 预算/提醒/外部渠道配置 | 同步账号业务配置与通知密钥，使用认证加密传输及手机安全存储，不把配置密钥写入日志或冲突摘要 |
| 主题/语言 | 暂按设备偏好保留，不随业务同步强制切换另一端界面；需要跨端统一时可另设偏好开关 |
| 操作/发送记录 | 每端保留来源，服务器发送结果可供 App 查看；不把历史日志导入当作新待发送事件，也不以旧发送日志错误阻止新提醒 |
| 账号密码/管理员/2FA 私钥/API Token | 不作为业务数据跨端复制；App 仅复用登录身份，保留既有账号安全约束 |

“完整备份包含所有密钥”继续有效。同步连接密码、会话令牌和设备认证材料不放入可跨设备自动恢复的普通业务负载。

## App 界面与状态

入口位于「设置 → 数据与隐私 → 服务器与同步」，不占用主要底栏。

字段：服务器地址（允许域名与部署子路径）、账号、密码显示/隐藏、按需显示两步验证码、自动同步开关。

流程：填写 → 测试连接 → 展示服务器与当前账号、协议兼容性 → 保存关联 → 首次合并预览 → 确认合并 → 自动同步。

账号与注册分支：

- 提供“已有网页账号，直接登录”与“没有网页账号，去注册”入口，注册目标始终为当前填写并验证的服务器。
- 未注册账号提示“该账号尚未在此服务器注册”，用户主动选择后进入注册页，不自动创建账号。
- 注册沿用服务器的用户名、邮箱和密码规则；按实际响应处理注册成功、邮箱验证或等待审批，不把未完成验证的账号标为已连接。
- 注册成功且满足服务器登录条件后，使用该账号登录、测试同步能力，再进入首次合并流程。
- 已有账号密码错误提示重新输入或找回密码，不一律引导重复注册。当前后端登录接口统一返回“用户名或密码错误”，无法直接据此判定账号不存在；实施时须提供与服务端策略一致的注册提示方式，不能让 App 猜测。
- 更换账号意味着另一份服务器资料，仍遵守账号隔离；保留原手机资料，不因注册或登录新账号直接上传、清空或合并旧数据。

- 测试只登录和读取能力，不上传、覆盖或删除业务数据。
- 地址/账号/密码改变后，原测试结果失效；不能测试 A 地址后保存 B 地址。
- 状态：未连接、测试中、待首次合并、同步中、已同步、离线待传、冲突待处理、登录过期、协议不兼容、失败待重试。
- 显示最近成功时间、待上传/下载数、冲突数量、最近脱敏错误，提供立即同步、重试、暂停、断开。
- 错误不显示成功色；同步中防止重复启动；最后成功时间只在本轮上传和下载均完成后更新。
- 服务器不支持同步协议时明确要求升级，不能用普通登录成功冒充支持自动同步。
- HTTPS 为默认连接方式；若需通过 HTTP 连接局域网 NAS，需明确告知凭据未加密的事实，并由用户主动启用该连接方式。不关闭证书校验。

## 数据一致性契约

### 标识、版本与隔离

- 每条可同步业务记录具备稳定同步标识，旧整数 ID 只用于本端存储。关联以稳定标识传输，在本地数据库映射为本端 ID。
- 每条记录具有服务器逻辑版本；每个账号具备单调递增变更游标。版本不依赖客户端墙上时间。
- 服务实例、账号和资料库世代共同决定同步目标，防止重装、恢复或切换地址后误用旧游标。
- 任意请求均验证账号所有权，禁止接受客户端传来的任意 `user_id` 作为授权依据。

### 写入与并发

- 新增、编辑、续费、重排、配置更新、导入替换与删除均需生成同步变更，不能只捕获手机操作而漏掉网页操作。
- 业务写入、记录版本与变更日志在同一事务提交。并发网页写入与手机同步必须共享有效的并发控制，不能只给 `/sync` 接口加锁。
- 同步请求包含设备 ID、操作 ID、记录标识、基准版本和操作内容。相同操作 ID 重试返回原结果，续费不能重复推进周期。
- 网页旧更新路径、导入、管理员代改和直接批量写入都要纳入迁移审查；未覆盖的写路径不能宣布同步一致性完成。
- 接收未知字段版本、非法关联、无效日期/金额或他人资源时拒绝并返回结构化错误，不静默截断或丢字段。

### 离线、删除与冲突

- 客户端本地业务事务同时写入持久化待同步队列；杀进程、重启或断网后队列仍存在。
- 服务端保存删除墓碑并支持过期游标的安全全量重建，不允许因日志清理造成记录复活。
- 客户端只在本地变更应用成功后推进下载游标；接收期间本地新增修改不能被并发下载覆盖。
- 两端同一基准版本独立编辑后，服务器拒绝覆盖并返回冲突引用。App 展示名称和不同字段，允许选择本地、服务器或合并后的结果。
- 冲突里的密钥默认隐藏，不在普通诊断日志中记录内容。
- 首次可能重复项只能作为候选提示，不能仅凭同名服务自动合并真实的两份订阅。

## 接口边界草案

复用现有登录与刷新接口，新增版本化同步协议。名称待实现时固定为以下契约，避免复用备份路由承担在线同步。

| 接口 | 作用 |
| --- | --- |
| `GET /api/sync/v1/capabilities` | 登录后验证服务器/账号/协议/资料库世代及限制 |
| `GET /api/sync/v1/changes?cursor=...&limit=...` | 分页拉取增量与墓碑，返回稳定下一游标与是否有后续 |
| `POST /api/sync/v1/push` | 幂等提交带基准版本的操作，返回已接收/冲突/拒绝结果 |
| 认证资源上传/下载接口 | 按资源内容标识交换图标，校验格式、大小、账号访问权限 |

错误沿用 FastAPI 的 `detail` 风格，加入稳定错误代码；区分认证失败、无权限、协议不支持、版本冲突、失效游标和可重试故障。页大小、负载大小与上传资源上限需显式校验。

## 自动执行与通知职责

- 本地保存后触发合并上传，App 打开/回前台/恢复网络时拉取；前台可低频检查服务器变化，重试退避并合并并发触发。
- Android 后台使用系统允许的任务机制，不承诺关闭 App 后秒级同步；界面显示最近实际成功时间和排队状态。
- 连接服务器的模式下，外部通知默认由服务器执行，App 保留手机本地通知，避免两端重复发送同一外部提醒。离线本地提醒继续有效。
- 接收续费/删除/提醒配置变化后重排本地计划；只有确认写入成功的结果才能影响通知。

## 测试与验收

测试位置建议：`backend/tests/test_sync*.py`、`frontend/src/sync/*.test.js`。不使用真实账号或生产数据库做破坏性验证。

实施后执行命令：

```powershell
# backend 工作目录，使用现有虚拟环境
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_sync*.py"

# frontend 工作目录
node --test src/sync/*.test.js
npm run test:android-preview
npm run build:android-preview
npm run build
```

核心场景：

- 正确/错误地址、未注册账号的注册引导、注册成功/重名/邮箱验证/审批响应、已有账号密码错误、TOTP、已禁用账号、过期令牌、旧服务器、子路径部署。
- 网页新增到手机、手机新增到网页；全部字段、分类/支付/捆绑包、图标、自定义币种及密钥配置完整一致。
- 两端修改不同记录自动合并；同一记录双改与删改冲突不丢任何一方内容。
- 离线多次修改、断电重启、请求重复、响应丢失、分页中断后恢复；续费只执行一次。
- 普通删除、批量删除、网页导入替换产生正确墓碑；过期游标重新建立基线不复活删除。
- 并发网页/手机写入、跨账号攻击、切换账号/服务器、备份恢复后世代变更。
- 图标可离线读取，资源丢失可重取；客户端失败时不推进游标或误报已同步。
- App 关闭/前台切换、省电限制、Wi-Fi/移动网络变化；服务器外部通知与手机本地通知职责不重复。

## 完成标准与边界

完成必须具有实际持久化客户端、服务器协议、双端真实数据联调和 OPPO 真机证据。只有设置页、登录测试、备份轮询或内存演示不算实现 debug22。

不新增团队协作、多账号同时混合、第三方云或收费服务。不保存明文登录密码，不跳过 TLS 校验，不自动发布或使用用户实际凭据。实现只在隔离 SQLite 测试库联调，未部署生产服务器。
